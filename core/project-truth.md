# Project Truth

Project Truth separates publishable evidence from assumptions.

## Evidence classes

### FACT
Verified from user-supplied information, repository content with clear authority, connected source, or authoritative external source when research was requested.

### REQUIREMENT
Explicit desired behavior or constraint. A requirement is not automatically a factual claim about the organization.

### RULE
Technical/product guidance such as accessibility, security, framework, or search requirements.

### DECISION
A reasoned implementation/content/design choice. Record important decisions when future maintainers need the rationale.

### ASSUMPTION
A working belief used to proceed. Never publish it as a business fact without verification.

### UNKNOWN
Information not currently available.

## Claim Gate

Before publishing a factual claim, ask:

1. What exact claim will a visitor infer?
2. What is the source?
3. Does the source support the exact claim?
4. Is it current enough for the claim?
5. If absent or conflicting, can the page work without it?

If unsupported: omit it, use a clearly marked placeholder in development, or surface the missing information as a blocker when essential.

Never fabricate testimonials, star ratings, awards, board affiliations, accreditations, rankings, years in operation, student counts, pass rates, pricing/fees, opening hours, phone numbers, addresses, staff identities, or compliance claims.
