# Decision Policy

Use these levels consistently:

- **MUST** — correctness, safety, truth, or explicit requirement.
- **SHOULD** — strong default; may be overridden for a documented project reason.
- **MAY** — optional technique.
- **PROJECT_SPECIFIC** — applies only when repository/project evidence supports it.

When choices conflict, prefer in this order:

1. safety and platform constraints;
2. explicit user requirement;
3. verified project truth;
4. healthy existing repository conventions;
5. selected workflow requirements;
6. discipline guidance;
7. framework adapter guidance;
8. profile defaults;
9. general ShriForgeAISkill defaults.

Avoid universal claims such as “always use library X” unless the rule truly applies to every supported project.
