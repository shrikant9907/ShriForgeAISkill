# Intent-First Architecture

Do not start with a generic page list. Start with people and outcomes.

## Model

`Audience → Intent → Information → Trust evidence → Surface → Content → CTA → Entity`

For each important audience:

1. What are they trying to accomplish?
2. What must they know first?
3. What doubts or trust concerns will block action?
4. What proof can truthfully resolve those concerns?
5. Should the answer be on a page, section, FAQ, form, notice, article, or contact action?
6. What next action should be available?
7. How should this connect to navigation and internal search/discoverability?

## Architecture rules

- One page may satisfy several closely related intents.
- Do not create thin pages solely to target keywords.
- Do not hide essential factual answers behind interaction unnecessarily.
- Keep primary navigation aligned with users' mental models, not internal org charts.
- Preserve useful existing URLs unless a migration provides a redirect plan.
