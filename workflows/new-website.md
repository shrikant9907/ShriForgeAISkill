# New Website Workflow

Use when creating a new production content/marketing/institutional website.

## Sequence

1. Define audiences, business/user outcomes, constraints, and truth sources.
2. Build intent-first architecture; do not start with a generic sitemap.
3. Establish content model and required factual inputs.
4. Choose visual direction and design-system foundations.
5. Choose architecture/framework based on project requirements; do not force Next.js if another stack is specified.
6. Build foundational layout, navigation, tokens, typography, metadata, error/not-found behavior.
7. Implement core pages/features in priority order.
8. Add search discoverability, accessibility, responsive behavior, performance, security/privacy.
9. Validate release gates and iterate.

## Required disciplines

`product-requirements`, `information-architecture`, `ux`, `visual-design`, `content`, `frontend-engineering`, `responsive-design`, `accessibility`, `testing`.

Search/performance/security/deployment become required when applicable to production scope.


## Contract

- Inspect before editing when a repository exists.
- Establish project truth when factual content is involved.
- Load only required disciplines and one adapter if needed.
- Map change surface before shared or risky changes.
- Validate proportionally and re-run affected checks after fixes.
- Finish with an explicit completion state for substantial work.
