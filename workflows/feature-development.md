# Feature Development Workflow

Use for a new page, section, form, interaction, or focused capability.

## Sequence

1. State user outcome and acceptance condition.
2. Inspect analogous existing patterns.
3. Map affected routes/components/data/metadata/tests.
4. Decide whether content truth, search, accessibility, privacy, or security are implicated.
5. Implement the smallest coherent feature.
6. Test happy path, relevant edge/error states, and regressions.

Do not redesign unrelated parts of the site.


## Contract

- Inspect before editing when a repository exists.
- Establish project truth when factual content is involved.
- Load only required disciplines and one adapter if needed.
- Map change surface before shared or risky changes.
- Validate proportionally and re-run affected checks after fixes.
- Finish with an explicit completion state for substantial work.
