OPENAI CODEX GUIDE

Use ShriForgeAISkill as repository guidance in Codex.

Codex can use ShriForgeAISkill when it can read the skill repository files. Because native skill discovery can vary by product/runtime, the portable method is to make the skill available to Codex and explicitly instruct it to read SKILL.md before the project task.

Portable Codex setup

Keep ShriForgeAISkill in the same workspace, as a subdirectory, or otherwise in a location Codex can read. Then start the task with an explicit instruction like:

Read /path/to/ShriForgeAISkill/SKILL.md before editing this project.
Follow ShriForgeAISkill's task classification, Project Truth,
intent-first architecture, selective routing, change-surface analysis,
and applicable release gates.

Only load the modules needed for this task.

Then describe the actual website outcome

Audit and improve this website for production.

Preserve healthy architecture and verified content.
Fix blocking UX, responsive, accessibility, SEO/AEO/GEO,
performance, security and testing issues where possible.
Return PASS, PASS_WITH_NOTES, BLOCKED or FAIL with evidence.

What if my Codex environment has its own project-instruction file?

Keep tool-specific project instructions small. Point them to the ShriForgeAISkill root or SKILL.md instead of copying the entire skill into another file. That reduces duplication and lets the repository remain the canonical methodology.

What should Codex load?

Start with SKILL.md. Based on the task, load one matching workflow, only the necessary disciplines, one framework adapter when relevant, and a domain profile only when it adds project-specific value.

Important portability rule

Do not assume Claude Code paths such as .claude/skills/ are special to Codex. They are shown in this project as Claude Code installation examples. In Codex, the requirement is that the agent can read the skill files and is explicitly instructed to follow them.
