GETTING STARTED

Use ShriForgeAISkill with your AI coding agent.

ShriForgeAISkill is a repository-based production web engineering methodology. Claude Code can install it as a skill; Codex and other agents can use it by reading SKILL.md directly when the repository is available to them.

1. Choose how your tool will load the skill

Claude Code

Native skill-directory setup

Clone the repository into a supported Claude Code skills directory. The folder containing SKILL.md is the skill root.

Claude Code instructions →
OpenAI Codex

Repository instruction setup

Make ShriForgeAISkill available in the workspace and explicitly tell Codex to read SKILL.md before the task.

Codex instructions →
Other agents

Portable manual setup

Any coding agent that can read local/repository files can follow the same master contract when you point it to the skill root.

2. Generic setup for any repository-aware AI tool

The portable path is simple: make the ShriForgeAISkill repository readable to the agent, then give it one explicit instruction before your project request.

Before working on this project, read the ShriForgeAISkill SKILL.md file.
Follow its task classification, Project Truth, selective routing,
change-surface analysis and applicable quality gates.
Load only the workflow, disciplines, adapter and profile needed
for this task. Do not invent project facts.

Do not assume every AI tool supports automatic Agent Skill discovery. If native discovery is unavailable, the explicit instruction above is the compatibility layer.

3. Give the agent an outcome, not a pile of implementation instructions

Describe the website, audience, constraints and any verified facts you already know. ShriForgeAISkill is designed to derive the implementation workflow from the outcome.

Build a production-ready website for a school in India.

The verified school facts are in the existing repository.
Make it trustworthy, mobile-first and distinctive.
Handle architecture, visual direction, implementation, SEO,
AEO/GEO, accessibility, performance, security and testing.
Do not invent affiliations, achievements or statistics.
Run applicable release gates before claiming completion.

4. For an existing project, tell the agent to preserve healthy architecture

Inspect this repository first.
Add an admissions page using the existing design system and conventions.
Map the change surface before editing.
Preserve healthy infrastructure and business logic.
Validate navigation, mobile behavior, accessibility, metadata and tests.

5. Know what completion means

ShriForgeAISkill uses four explicit release states rather than vague “done” language.

PASSApplicable gates passed.
PASS_WITH_NOTESReady with non-blocking limitations.
BLOCKEDMissing information, credentials or infrastructure prevents completion.
FAILKnown blocking defects remain.

6. Validate the skill repository itself

python scripts/validate_repo.py
python -m unittest discover -s tests -v

These checks validate repository structure, skill metadata, schemas, workflow contracts and key routing/truth expectations.
